Working rules

How I keep agent output trustworthy

An agent with access produces plausible work fast, and plausible is the risk. Claude Code's own usage report for the month counted 13 times I redirected a wrong approach. These rules came out of those corrections.

  1. 1

    Make it say what it inferred

    Every artifact gets the question: which parts did you verify and which did you guess? On the lineage map, the guessed parts were the ones that were wrong.

  2. 2

    Read the whole source first

    On the forecasting review, the agent critiqued the proposal after reading one tab of two multi-tab workbooks. I had it reread everything before either of us drew conclusions.

  3. 3

    Use the stakeholder's formula, not a reasonable substitute

    Twice the agent chose a metric that was defensible and different from the one the business already used. Matching the existing definition is what makes a number comparable.

  4. 4

    Ask whether it is a permissions problem before adding a tool

    When a metadata pull failed, the suggestion was to install a second connector described as official. I asked for confirmation, and it turned out to be a third-party package.

  5. 5

    Write the lesson where the agent will load it

    After a difficult request I wrote up what went wrong on both sides and had it saved to persistent memory, so later sessions started with those rules already loaded.
